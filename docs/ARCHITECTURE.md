# Architecture and editing map

EKG Lab is a static browser application using HTML, CSS, native JavaScript modules, canvas, and vendored Three.js. **`dist/` contains editable application source**, despite its name. The entry point is [`dist/index.html`](../dist/index.html), which loads `app.js` and then `lab.js`; no frontend compilation is required to edit those files. Serve the runtime over HTTP so module imports and asset fetches work. See the [README](../README.md) for setup and asset preparation.

## Runtime boundaries

[`lab.js`](../dist/lab.js) owns the six hash routes, templates, shared lesson state, event binding, and the animation clock for Modules 2, 3, 5's recording view, and 6. Module 4 explicitly freezes its measurement snapshot. Route changes destroy the previous scene and charts before constructing the next view; retain this cleanup when adding UI.

Module 1 is a separate document, embedded by [`voltage-lesson.js`](../dist/voltage-lesson.js). Its iframe isolates styles, keyboard handling, chapter history, and clock. The wrapper remembers the selected chapter/scroll position and removes the browsing context on exit. Its own entry point is [`cardiac-voltage/app.js`](../dist/cardiac-voltage/app.js).

Module 5's fitted view is another explicit boundary: [`FitExplorer`](../dist/fit-explorer.js) owns loading, playback, charts, tissue sampling, and cleanup while active. The main lesson animation loop skips its ordinary scene updates during that view.

## Signals and data flow

| Path | Data flow | Interpretation |
| --- | --- | --- |
| Teaching ECG and rhythm builder | `ecg.js` or `pathology-model.js` → shared time/state → `charts.js` and `HeartScene` | Generated teaching signal; the Sandbox schedules atrial and ventricular events separately. |
| Clinical recording | `data/clinical-*.json` and supplemental source data → `decorateClinicalData()` → recorded chart samples; `recordState()` → reference-heart animation | Recorded samples remain separate from estimated timing and illustrative spatial activation/motion. |
| Fitted clinical model | `data/pathology-fits/cases/*.json` + `cardiac-voltage/data/heart-model.json` → `FittedField`, `HeartSurface`, `FitChart`, `FitAPPanel` | Saved offline fit and source-field hypothesis. Browser playback does not repeat optimization. |
| Module 1 whole heart | `heart-data.js` → optical arrays/metadata **or** model geometry, source parameters, and saved ECG arrays → chapter renderer and site comparisons | Measured normalized optical fluorescence and modeled membrane voltage remain separate modes. |

In the fitted path, [`fit-model.js`](../dist/fit-model.js) evaluates action potentials at source sites **before** interpolating voltage onto displayed geometry. The displayed ECG prediction is supplied by the offline volume-conductor calculation, not generated by adding display pixels. Preserve the source-index/render-weight relationship when changing geometry or field formats.

The shared scene loads anatomical assets from `models/` and the electrical atlas from `data/electrical-atlas.json` plus its referenced binary. [`electrical-field.js`](../dist/electrical-field.js), the conduction modules, and [`cardiac-motion.js`](../dist/cardiac-motion.js) supply electrical maps, event timing, and reference motion. A schematic lead-axis overlay is distinct from the fitted model's forward operator.

## Interaction and rendering invariants

- **Seek continues:** shared `seekTime()`, fitted `seek()`, and Module 1's jump/seek handlers resume animation. Explicit Pause and finite record boundaries still stop it. Module 4 and Sandbox configuration changes have deliberate stationary behavior.
- **Gain is a display scale:** Module 3 uses one mm/mV gain across leads and computes sufficient row height. Do not normalize each lead separately or alter its samples to make it taller.
- **Camera input must not create permanent overlay work:** the shared scene caches viewport/control bounds and updates SVG coordinates only when the accumulated projected change warrants a repaint. Preserve its subpixel threshold, label obstacles, and ordering of layout reads before SVG writes. The v22 change targets post-interaction overhead without changing camera damping or scientific data.
- **Keep separate lifecycles:** dispose scene resources, observers, handlers, and chart instances when replacing a route or fitted view. Avoid installing a second animation loop for ordinary controls.
- **Preserve evidence boundaries:** do not replace measured ECG samples with generated shapes, present reference motion as measured mechanics, or describe fitted parameters as uniquely inferred patient physiology.

## Verification and research tooling

Focused regression scripts include `scripts/check-scene-interaction.mjs` (post-drag overlay scheduling), `check-lead-axis-layout.mjs` (caption geometry), `check-playback-gain.mjs` (seek/caliper routing and gain bounds), `check-clinical-chart-scale.mjs`, `check_recorded_arrhythmias.mjs`, and `check-electrolytes.mjs`. Use the README's supported check commands and perform visual checks of the affected module; these numerical/DOM checks do not replace browser interaction review.

Offline imports and fitting live under `scripts/` and `data-source/`. The shipped research package also has [verification notes](../dist/research/verification/README.md) and [regeneration notes](../dist/research/regenerated-fits/README.md). Existing fitting scripts document historical calculations and may need their stated inputs and scientific environment; routine UI development and playback use the finished datasets and do not require refitting.
